  1→# SayIn
  2→
  3→> 把手机变成电脑的输入法。
  4→
  5→Mac Mini 没有麦克风？打字不便？用手机自带的输入法（键盘 / 语音）写内容，点一下就传到电脑。手机零安装，浏览器打开即用。
  6→
  7→**开源协议：Apache-2.0**

 10→
 11→## 为什么做
 12→
 13→这不是一个商业项目，而是一个开发者为了解决自己的痛点，顺手做出来的小工具。
 14→
 15→> 我有一台 Mac Mini，性能很强，但它没有麦克风，也没有摄像头。想用语音输入、想随手打几个字发给同事，只能抱个外接麦，或者对着手机敲完再复制粘贴——太麻烦了。
 16→
 17→于是就有了 SayIn：手机当输入板，电脑当接收端。手机不用装任何 App，浏览器打开就能用。打字、语音都行，写完一点「发送」，文字就出现在电脑光标处。就这样，Mac Mini 终于有了「嘴」。

 20→|:---:|:---:|
 21→| **0** | 手机端需安装的 App |
 22→| **1** | 条 npm 命令即可启动 |
 23→| **2** | 台设备（手机 + 电脑） |

 27→## 它能解决什么
 28→
 29→如果你也遇到过下面这些场景，SayIn 大概能帮上忙。
 30→
 31→### 台式机没有麦克风
 32→
 33→Mac Mini、组装机、没有内置麦的显示器，想语音输入只能外接设备。SayIn 直接用手机当麦克风和输入板。
 34→
 35→### 手机打字再复制粘贴
 36→
 37→在手机上写好长文，再手动复制、切到电脑、粘贴——步骤太多还容易丢。SayIn 一点「发送」直接到位。
 38→
 39→### 跨设备传文字太繁琐
 40→
 41→想把手机上的一段文字弄到电脑上，得绕一圈：发给「文件传输助手」、贴到云笔记、或邮件发自己。SayIn 只传文字，一条局域网 WebSocket 直连，实时又省事。
 42→
 43→### 系统语音输入不好用
 44→
 45→macOS 听写要联网、识别慢、还要按热键。SayIn 用你手机上熟悉的输入法，想怎么打就怎么打。
 46→
 47→### 长文输入太累
 48→
 49→在电脑键盘上敲几百字还行，上千字就累了。用手机熟悉的输入法，躺着走着都能写，写完一点「发送」就到电脑。
 50→
 51→### 外接话筒又贵又不随身
 52→
 53→一个像样的 USB 麦克风要花几百块，而且你不会时刻把它带在身边。手机却是你时时刻刻握在手里的，它本就是最现成的输入设备。

 57→## 小而美，不臃肿
 58→
 59→没有账号、没有云端、没有订阅。一个 Node.js 文件跑起来，数据全在你自己电脑上。
 60→
 61→- **手机零安装** — 不用下载 App，不用装插件。手机浏览器打开一个网址就能用，支持添加到主屏幕像 App 一样全屏。
 62→- **纯局域网，数据不出门** — 手机和电脑在同一 WiFi 下直连，文字通过 WebSocket 实时传输，不经过任何第三方服务器。
 63→- **一条命令启动** — `npm start` 就能跑起来。依赖只有一个 WebSocket 库，体积小、启动快、不占资源。
 64→- **跨平台** — 支持 macOS 和 Windows。macOS 还能自动粘贴到光标位置，Windows 可手动复制粘贴。
 65→
 66→```
 67→手机                          电脑
 68→ │                            │
 69→ │  WebSocket 局域网直连       │
 70→ │  ──────────────────────────►│
 71→ │  手机输入法打字/语音 → 发送   │  光标处出现文字
 72→```

 76→## 功能一览
 77→
 78→围绕「输入 → 传输 → 落地」全链路打磨，细节足够日常使用。
 79→
 80→| 功能 | 说明 |
 81→|------|------|
 82→| **手机输入 电脑接收** | 用手机输入法打字或语音识别，点发送实时传到电脑接收窗口 |
 83→| **应用切换** | 一键获取电脑运行中的应用，切换并自动粘贴到目标软件 |
 84→| **自动粘贴** | 发送后自动粘贴到电脑光标位置（macOS 需授权辅助功能权限） |
 85→| **回车发送** | 粘贴后自动模拟回车，适配微信、QQ 等需要回车发送的场景 |
 86→| **追加模式** | 新内容追加到输入框末尾而非覆盖，适合分段撰写长文 |
 87→| **历史记录** | 发送记录持久化保存，支持一键重新发送，误删也不怕 |
 88→| **软件白名单** | 在设置页筛选常用软件，避免运行中列表太长干扰选择 |
 89→| **PWA 支持** | 添加到手机主屏幕，像原生 App 一样全屏使用，无地址栏 |
 90→| **设置持久化** | 所有设置自动保存，重启服务不丢失 |

 94→## 快速开始
 95→
 96→### 环境要求
 97→
 98→- [Node.js](https://nodejs.org/) 18+
 99→- 手机和电脑在同一局域网（同一 WiFi）
100→
101→### 安装与运行
102→
103→```bash
104→git clone https://github.com/joyapple/SayIn.git
105→cd SayIn
106→npm install
107→npm start
108→```
109→
110→启动后会打印访问地址：
111→
112→```
113→╔══════════════════════════════════════════════════════════════════╗
114→║                       ✦  SayIn  已启动  ✦                       ║
115→║                  手机写字板 → 电脑 · 优雅输入                    ║
116→╠══════════════════════════════════════════════════════════════════╣
117→║  💻 电脑接收窗口：http://localhost:8000/desk                     ║
118→║  ⚙️  设置页面：    http://localhost:8000/settings                ║
119→║  📱 手机入口：     http://192.168.x.x:8000                       ║
120→║  🔒 手机(HTTPS)：  https://192.168.x.x:8443                      ║
121→╚══════════════════════════════════════════════════════════════════╝
122→```
123→
124→### 使用步骤
125→
126→1. **电脑端**：浏览器打开 `http://localhost:8000/desk` 接收文字
127→2. **手机端**：用手机浏览器打开 `https://电脑IP:8443`（推荐 HTTPS）
128→3. **输入发送**：在手机上用输入法打字或语音输入，点「发送」即可
129→4. **切换软件**：点击顶部软件栏，选择电脑上的目标应用

133→## PWA 安装（推荐）
134→
135→为了获得类似原生 App 的全屏体验（无地址栏），请通过 **HTTPS** 访问并添加到主屏幕。
136→
137→### Android（Chrome / Edge）
138→
139→1. 手机浏览器打开 `https://电脑IP:8443`
140→2. 首次访问时信任自签证书（点击「高级」→「继续前往」）
141→3. 页面顶部会弹出「安装 SayIn」提示，点击「安装」
142→4. 从主屏幕打开即可全屏使用，无地址栏
143→
144→### iOS（Safari）
145→
146→1. Safari 打开 `https://电脑IP:8443`
147→2. 首次访问时信任自签证书
148→3. 点击底部「分享」→「添加到主屏幕」
149→4. 从主屏幕打开即可全屏使用
150→
151→> **注意**：通过 HTTP（端口 8000）添加到主屏幕会保留地址栏。必须使用 HTTPS（端口 8443）才能实现全屏 PWA 体验。

155→## 设置页面
156→
157→打开 `http://localhost:8000/settings` 配置以下选项：
158→
159→| 设置项 | 说明 |
160→|--------|------|
161→| 自动粘贴 | 发送后自动粘贴到电脑光标位置（需辅助功能权限） |
162→| 追加模式 | 新内容追加到输入框末尾，而非覆盖 |
163→| 粘贴后回车 | 自动粘贴后模拟回车，适配需要回车发送的软件 |
164→| 软件白名单 | 筛选可切换的软件，留空则显示全部运行中应用 |
165→
166→所有设置自动持久化到 `data/settings.json`，重启不丢失。

170→## macOS 权限配置
171→
172→### 辅助功能权限（自动粘贴需要）
173→
174→如果开启了「自动粘贴」功能，需要授权辅助功能权限：
175→
176→1. 打开 **系统设置 → 隐私与安全性 → 辅助功能**
177→2. 将运行 SayIn 的终端应用（如「终端」「iTerm」）添加并勾选
178→
179→### 信任自签证书（HTTPS 访问）
180→
181→首次通过 HTTPS 访问时，浏览器会提示证书不受信任：
182→
183→- **Android Chrome**：点击「高级」→「继续前往」
184→- **iOS Safari**：点击「显示详细信息」→「访问此网站」
185→- **macOS**：可双击 `certs/cert.pem` 导入到钥匙串并设为始终信任

213→## 技术架构
214→
215→```
216→手机浏览器                    电脑浏览器
217→   │                            │
218→   │  WebSocket (文字传输)       │  WebSocket (文字接收)
219→   │                            │
220→   └─────────► server.js ◄──────┘
221→                  │
222→                  ├── HTTP  (8000) — 手机入口 + 电脑端页面
223→                  ├── HTTPS (8443) — PWA 全屏模式
224→                  ├── 静态文件服务
225→                  ├── 应用列表获取 (lsappinfo + ps)
226→                  ├── 自动粘贴 (osascript keystroke)
227→                  └── 设置/历史持久化
228→```
229→
230→- **通信**：WebSocket 实时双向传输，纯局域网，不经过第三方服务器
231→- **应用列表**：`lsappinfo`（获取显示名）+ `ps`（兜底补充），零权限
232→- **应用切换**：`open -a`（零权限）+ `osascript`（兜底）
233→- **自动粘贴**：`pbcopy` 写入剪贴板 + `osascript` 模拟 Cmd+V
234→- **PWA**：manifest.json + Service Worker 离线缓存

238→## 常见问题
239→
240→### 手机打不开页面？
241→
242→- 确认手机和电脑在同一 WiFi
243→- 确认电脑防火墙未阻止 8000/8443 端口
244→- 尝试用 HTTPS（8443 端口）访问
245→
246→### 发送后电脑没有内容？
247→
248→- 刷新电脑端 `http://localhost:8000/desk` 页面
249→- 确认页面显示「已连接」
250→
251→### 自动粘贴失败？
252→
253→- macOS 需要在「系统设置 → 隐私与安全性 → 辅助功能」中授权终端应用
254→- Windows 暂不支持自动粘贴，可手动复制粘贴
255→
256→### PWA 打开后有地址栏？
257→
258→- 必须通过 **HTTPS**（8443 端口）添加到主屏幕
259→- HTTP（8000 端口）添加到主屏幕会保留地址栏
260→- iOS 请使用 Safari 添加，Android 请使用 Chrome/Edge
261→
262→### 识别不到运行中的软件？
263→
264→- 点击设置页「加载运行中应用」刷新列表
265→- 系统自带应用（访达、控制中心等）会自动过滤
266→- 可手动添加白名单指定常用软件
